1. Introduction

TSVG is a video format whose content is a small program rather than pixels. A TSVG document describes vector shapes, text and images on a timeline, plus the options a viewer may choose: language, audio mix, theme and layout. An engine draws every frame live. So a TSVG video:

  • stays sharp at any zoom and any screen density;
  • is one file for many variants (e.g. 2 layouts × 2 languages × 3 audio mixes × 2 themes = 24 videos);
  • is cheap to produce (text in, no encoding) and cheap to change (edit a line, the video changes);
  • contains no HTML and no JavaScript. Engines can be native (web canvas, Flutter, Android, iOS) and still be safe;
  • plays like a real video: timeline, chapters, ±10 s, speed, captions, scrub previews.

The core rule: a frame is a pure function of (time, options, layout). Every engine MUST draw the same picture for the same inputs, within the tolerance of its rasteriser (§12).

Keywords MUST, SHOULD and MAY are used as in RFC 2119.

3. Document

<tsvg version="0.1" title="@title" font="Inter, Noto Sans Gujarati" [duration="…"]>
  <layouts> <options> <mixes> <themes> <strings> <defs> <assets>
  <music …/>*
  <backdrop> nodes </backdrop>
  <timeline> <scene>… </timeline>
  <overlay> nodes </overlay>
  <voices> (written by tools) </voices>
</tsvg>

Order of sections is free. Unknown elements MUST be ignored (forward compatibility). The root font is the default family list for text. duration overrides the computed end of the last scene.

3.1 Layouts

<layouts>
  <layout id="landscape" w="1920" h="1080"/>
  <layout id="portrait"  w="1080" h="1920"/>
</layouts>

A layout is a coordinate space in abstract units (not pixels). The engine scales it to fit the screen. With "auto", the player picks the layout whose aspect ratio is closest to the screen (log-ratio distance). The first layout is the default. The layout id is a variant tag (§4).

3.2 Options and mixes

<options>
  <option id="lang" label="Language" default="en">
    <choice id="en" label="English" tts="kokoro:af_heart"/>
    <choice id="gu" label="ગુજરાતી"  tts="sarvam:shubh"/>
  </option>
  <option id="mix" label="Audio" default="full"> <choice id="full"/> <choice id="speech"/> </option>
  <option id="theme" default="dark"> <choice id="dark"/> <choice id="light"/> </option>
</options>
<mixes>
  <mix id="full"   voice="1" music="0.35" sfx="0.7"/>
  <mix id="speech" voice="1" music="0"    sfx="0"/>
</mixes>

Options are what a viewer, or an embedding app, may choose. Any number of options may exist; four ids have meaning to engines:

idmeaning
langSelects strings (@id), voice clips and captions.
mixEach choice names a <mix>: gain per audio bus (voice, music, sfx, or custom buses).
themeEach choice names a <theme> (§3.3).
anything elseAvailable as a variable in expressions and as a variant tag. For example, <option id="detail"> with choices brief/full lets one video skip or show sections via when.

Every option value is a variable in expressions (lang == 'gu') and a variant tag (size.gu="40"). The tts attribute on a lang choice tells tsvg bake which voice to record with (§9). Players MUST let the viewer change every option while playing, and MAY accept initial values from the host (URL, API).

3.3 Themes and strings

<themes>
  <theme id="dark"  bg="#0e1117" fg="#eef1f7" accent="#7aa2ff"/>
  <theme id="light" bg="#f6f3ec" fg="#1b1e26" accent="#2f5bea"/>
</themes>
<strings>
  <s id="title" en="TSVG" gu="TSVG"/>
  <s id="hello" en="Hello {lang}" gu="નમસ્તે"/>
</strings>

A theme is a set of tokens, used as $name. bg paints the frame background, and fg is the default text colour. A string has one attribute per language. A missing language falls back to en, then to the first attribute. Strings may contain {expr} templates.

3.4 Defs

<defs>
  <fn id="wave" args="i,speed">sin(t*speed + i*0.6)</fn>
  <symbol id="dot"><circle r="10" fill="$accent"/></symbol>
  <linear id="ink" x1="0" y1="0" x2="620" y2="0"><stop at="0" color="$accent"/><stop at="1" color="$pink" opacity="1"/></linear>
  <radial id="glow" x="0" y="0" r="330" [fx fy]><stop …/></radial>
  <clip id="porthole"><circle r="=210 + 14*sin(T*2)"/></clip>
  <mask id="wipe"><rect w="=760*ease(T/1.6,'io')" h="280" y="-140" fill="#000"/></mask>
  <data id="sales" v="12, 28, 19, 44"/>          <!-- 0.2: a list; numbers stay numbers, the rest are strings -->
</defs>

Defs may use expressions. They are evaluated with the variables of the node that uses them, so clips and masks can animate.

3.5 Assets and fonts

<assets>
  <asset id="pad"  src="assets/pad.m4a"/>        <!-- type by extension: audio | image | font -->
  <asset id="photo" src="images/photo.jpg"/>
  <font family="Inter" src="fonts/Inter.ttf" [weight="1 1000"] [style="normal"]/>  <!-- weight: one value, or a range for variable fonts (default) -->
</assets>

Engines MUST support PNG, JPEG, WebP images; AAC (.m4a) and MP3 audio; TTF/OTF fonts. Authors SHOULD ship audio as AAC .m4a (what tsvg bake writes): it plays everywhere, while Ogg Opus doesn't play on Apple's native players (iOS/macOS AVPlayer). Engines SHOULD wait for fonts before drawing the first frame (with a timeout). Wherever a node takes an asset (src), the value may be an asset id or a relative path.

3.6 Timeline

<music src="pad" [start="0"] [loop="1"] [vol="0.8"] [bus="music"] [when="…"]/>
<timeline [in="fade 0.5"]>
  <scene id="intro" dur="7|auto" [start="…"] [chapter="@ch1"] [in="push 0.6 left"] [min pad gap]>
    <say at="0.6" text="@vo1" [speak="@vo1_say"] [src.en="clip.m4a"] [voice="…"] [when]/>
    <sfx at="0.3" src="whoosh" [vol] [bus="sfx"]/>
    …nodes…
  </scene>
</timeline>

Scenes play in order. Each starts where the previous one ended, unless it gives start. Time is continuous seconds. There is no frame rate in the file; engines draw at the display rate. A scene with chapter adds a chapter mark at its start. At or after the end of the video, the last scene holds its final frame.

Transitions (0.6). <scene in="push 0.6 left io">: kind, seconds (0.6), direction (left), ease (io), in any order after the kind. <timeline in="fade 0.5"> sets it for every scene; in="none" turns it off; the first scene has none. Kinds: fade slide push wipe zoom iris blur. A transition plays over the first seconds of its scene; underneath, the previous scene keeps running (T past its end). Timing does not change.

Auto timing (0.5). dur="auto": the scene lasts as long as its narration in the chosen language: the end of its last <say> + pad (0.8), at least min (2; may be an expression). In such a scene a <say> without at follows the previous line + gap (0.3); the first starts at 0.4. A line's length is its baked clip's (<voice dur> for that language), else its dur, else an estimate (0.42 s a word). dur, start and a say's or sfx's at also take variants (dur.gu="9"). So the timeline belongs to an option set: engines lay it out per option set (reference: TSVG.forOptions(doc, opts)), and a player's duration, chapters and audio follow the chosen language. Inside a scene, cue('id') / cueEnd('id') are the scene time at which that line starts / ends (cue(0) = the scene's first line), so animations can follow the voice: at="=cue('v2')".

Auto layout (0.5). A row places its children left to right, a col top to bottom, a grid in cols columns of equal width (the widest item, or w shared out) and rows as tall as their tallest item. Each child has a box: rect/image w×h (its ax ay shifts its origin inside it), circle 2r, ellipse 2rx×2ry, text measured with its font (wrapped at maxw; y is the block's centre and align its anchor), a nested container its own size, group/use/path their w h attributes (0). The child is drawn translated to its place; its own x y still add (entrance animations). repeated children are items each. when/only false takes a child out of the flow; at keeps its place, so staggered entrances never move the others. grow="1" on a rect/image/group/container takes a share of the space left on the main axis; align="stretch" sizes them on the cross axis. Layout is computed every frame, so animated sizes reflow.

Repeat (0.2). Any node may carry repeat="n" (number or expression, at most 10 000) and as="i" (default i). The node is drawn n times; in its own attributes and its whole subtree the variable i is 0…n−1 and i_n is n. Repeats nest, e.g. a grid is a repeated group of repeated circles.

Common to all: blur (0.2; Gaussian blur radius in layout units; for a group, engines may blur each child or the group layer) fill stroke sw (stroke width, 0) cap round|butt|square (0.7, round) filter (0.9: grayscale(a) sepia(a) contrast(a) brightness(a) saturate(a) hue(deg) invert(a) blur(px) opacity(a), in order; colour grades for images, clips and whole groups) skx sky (0.9, skew in degrees) opacity (multiplies down the tree) rot degrees scale, sx sy per-axis scale (0.2.2; multiply with scale; card flips) dash="24 16" (0.2.2; stroke dash pattern) (around the shape's centre; around x,y for group/use/path/text) shadow clip mask blend, plus timing: at (appears at, scene time), dur (visible for), when (expression; hidden when 0), only="portrait gu" (visible only if any tag is active).

6. Paint and effects

  • Paint: fill/stroke take a colour, a token, or url(#gradient). Gradient coordinates are in the node's own coordinate space. Stops take at (0–1), color and opacity; all may be expressions.
  • Clip: clip="url(#id)" clips the node, or a group's children, to the union of the clip's shapes (rect, circle, ellipse, path).
  • Mask: mask="url(#id)" keeps the node's pixels in proportion to the alpha of the mask's drawing. For group/use/path, the mask is in the node's coordinate space after its x y. Engines implement it as an offscreen layer composited with destination-in (Flutter: saveLayer + BlendMode.dstIn).
  • Shadow: shadow="dx dy blur color" in layout units. The colour may be a token. On a node with both fill and stroke, only the fill casts it.
  • Blend: blend = a Canvas composite operation (multiply, screen, lighter…). Optional for engines.

7. Animation

<text …>
  <anim prop="opacity" from="0" to="1" [at="0"] [dur="0.5"] [ease="out"]/>
  <keys prop="x" v="0:100; 1.2:300; 2:250" [ease="io"]/>
</text>
  • Anim times are relative to the node's own at, or else the nearest ancestor's at, or else the scene start.
  • <anim>: from/to default to the property's base value. Before at, the first anim of a property holds from; after at+dur, it holds to. Several anims on one property apply in document order. Once a later one has started, it wins.
  • <keys>: keyframes time:value separated by ;. It holds the first value before the first key and the last value after the last key.
  • Numbers interpolate linearly through the ease. Colours interpolate per RGBA channel. Morph (0.2): two strings with the same skeleton (the same text once every number is removed, e.g. path data with the same commands) interpolate number by number, so <keys prop="d"> morphs shapes. Anything else switches at the end.
  • Eases: linear in out io back elastic step (cubic in/out/in-out; see the reference engine for exact formulas).

8. Expression language

expr    := ternary
ternary := or ('?' expr ':' expr)?
or      := and ('||' and)*         and := cmp ('&&' cmp)*
cmp     := add (('=='|'!='|'<'|'>'|'<='|'>=') add)*
add     := mul (('+'|'-') mul)*      mul := pow (('*'|'/'|'%') pow)*
pow     := unary ('^' pow)?          unary := ('-'|'!') unary | atom
atom    := number | 'string' | "string" | name | $token | name '(' args ')' | '(' expr ')'
  • No assignment, loops, I/O or clocks. Evaluation always terminates and is deterministic.
  • + concatenates if either side is a string. % is floored modulo. Booleans are 1/0.
  • Variables: t video time, T scene time, p scene progress 0–1, sdur scene duration, dur video duration, W H layout size, portrait 1/0, layout id, every option id, $tokens, PI true false.
  • Functions: sin cos tan abs sqrt min max floor ceil round pow exp log atan2 sign clamp(v,a,b) lerp(a,b,k) step(e,x) smooth(a,b,x) fract ease(k,'name') fmt(n,digits) str rgba(r,g,b,a) mix(colorA,colorB,k) data('id', i) count('id') rand(seed) noise(x) s('id') num('0.1 0.2', i) fitw(a,bw,bh) fith(a,bw,bh) aspect('img') cue('say') cueEnd('say') nth('a | b', i) commas(n, d) since(t, 'id') idx(t, 'id') pulse(t, 'id', decay) (0.9 time lists such as a beat grid: seconds since the last time ≤ t, how many times ≤ t, and a 1→0 exponential pulse on each) (0.7: nth the i-th item of a |- or comma-separated list, $tokens resolved, numbers as numbers; commas 12840 → 12,840) (0.4/0.5: num the i-th number of a list; fitw/fith the size of a picture of aspect a fitted inside bw×bh; aspect width/height of a loaded image, 1.6 until known; cue §3.6) (s, 0.2.2: a string from <strings> in the current language) (rand = fract(sin(seed·12.9898+78.233)·43758.5453); noise = smoothstep-interpolated rand between integers) (data wraps the index around the list), plus document <fn>s (arguments become variables).
  • An unknown variable, token, string or function is an error. Validators report it (§13).

9. Audio, voices, captions

  • Buses. Every sound plays on a bus: <say> → voice, <music> → music, <sfx> → sfx (or its bus). The current <mix> sets each bus's gain. A missing bus gets gain 1.
  • Say lines. A <say> is one narration line. Its key is its id, else the string id of its text. text is also the caption. speak (optional) is the pronunciation text sent to TTS.
  • Clip lookup for language L: src.L on the say, else the <voice say="key" lang="L"> entry, else none. With no clip, a player MAY use on-device TTS; it MUST still show captions.
  • Voices table (written by tsvg bake): <voice say lang src dur hash engine/>. hash = sha1(engine|voice|text), so only changed lines are re-recorded.
  • Caption timing: from the say's start for the clip's duration (or dur, or 0.42 s per word, minimum 1.5 s).

9.1 Beat grids and ducking (0.9)

<music src="beat" loop="1" beats="beats"/>: tsvg bake (and make) detects the music's beats (onsets snapped to the dominant period), repeats them over the video when the music loops, and writes <data id="beats" from="…" v="0.18, 0.68, …"/> into the document; until then the list is empty. Use it with pulse(t, 'beats', 0.2), idx(t, 'beats') or <fx:beat>. <mix … duck="0.3"/>: while a line is spoken the music bus drops to duck× its level, with 0.25 s ramps (TSVG.duckAt); players and exports apply it.

10. Rendering model

  1. Pick the layout and options. Build the variant tags and the environment (§8 variables).
  2. Fill the frame with theme bg. Draw <backdrop> with T = t.
  3. For each scene active at t (start ≤ t < start+dur, or the last scene once t ≥ its end), draw its nodes with T = t − start.
  4. Draw <overlay>. Captions and controls belong to the player, not the frame.

Nodes draw in document order (painter's algorithm). Transforms compose down the tree: translate(x,y) for groups, then rotate/scale about the pivot.

11. Player requirements

Speed is the player's, not the document's. As with any video, playback rate is applied after rendering: the timeline clock and every audio clip run at the same rate, with pitch preserved. A document never declares or reacts to speed.

A conforming player MUST offer: play/pause, a seekable timeline with chapter marks, back/forward 10 s, playback position and duration, captions on/off, every document option, and layout auto/explicit. It SHOULD offer: speed, scrub previews (rendered frames, which are free here), double-tap sides to skip, pinch/scroll zoom that re-renders (never bitmap-scales), fullscreen, and keyboard shortcuts (space/k, j/l, arrows, 0–9, c, f).

12. Conformance

tests/cases.json lists (file, t, options, layout, width). tests/golden/*.png are the reference frames from the web engine in Chrome. Engines render the same cases and compare per pixel (max channel difference > 40/255 counts as off). The web engine must match its goldens exactly (0.3 % allowed). Other engines report their ratio; differences come mainly from font rasterisation and anti-aliasing.

13. Libraries and components

A library (.tsvgl) packages reusable parts: components (tags with props), styles (themes, fonts, gradients, symbols, <fn>s, music, backdrop) and document defaults (layouts, options, mixes). A document imports it and writes only content, so the same props always give the same video, with a fraction of the markup.

<tsvg version="0.3" title="ORCH-78">
  <import src="tsvg:report" as="r" key="ORCH-78"/>          <!-- params: key flows into the library -->
  <timeline>
    <r:title title="Libraries are live" say="Here is what changed."/>
    <r:list title="What changed" items="Imports | Components :: tags with props" say="Two things changed."/>
  </timeline>
</tsvg>

13.1 Import

<import src as …params/> is a direct child of <tsvg> (or of a library). src is tsvg:<name> (the built-in libraries of this engine release, served from jsr.io/@panth977/tsvg/<version>/libs/), jsr:@scope/pkg@1.2.3/path.tsvgl, a URL, or a path relative to the importing file. as is the prefix of its components (<r:title/>); other attributes set the library's params.

13.2 Library file

<tsvglib name="report" version="1.0.0" params="key=''" font="Inter" doc="…">
  <import src="../base/base.tsvgl" as="b" key="%{key}"/>
  <layouts>…  <options>…  <mixes>…  <themes>…  <strings>…  <defs>…  <assets>…  <music/>  <backdrop>…  <overlay>…
  <component id="title" props="title, sub='', say='', dur=7" doc="Opening scene"> … </component>
</tsvglib>
  • Merging. The document comes first, then its imports in order, then theirs. Layouts: the document's replace the library's. Options, mixes: merged by id (the first wins, so a document can redefine lang with more languages). Themes: merged by id, token by token (<theme id="dark" accent="#e4572e"/> changes one token). Music, backdrop, overlay: the library's only when the document has none. Fonts and assets nothing uses are dropped; <font only="gu"> ships only when a gu choice exists.
  • Names. A library's ids (defs, fns, data, strings, assets) become name__id, so they never clash. Inside the library they keep their short names; anywhere, alias:id points into an import: ref="b:tick", fill="url(#b:ink)", text="@b:hello", src="b:pad", s('b:x'), data('b:x', i), and a library's functions inside expressions: =b:wave(t).
  • Files. Paths are relative to the library file. Packages carry them under lib/.

13.3 Components

props="a, b=default, c?": a is required, b has a default, c defaults to empty (or <prop name doc default/> children). A use is <alias:id prop="…"/>; components declared in the document's own <defs> are used by their bare id. The body is a template, expanded statically before parsing:

%{p}the prop's value (in any attribute or text). %{a|b}: a, or b when a is empty. %{p#}: a short stable hash of the value (e.g. <say id="%{say#}">). %{_uid}: a stable id for this use.
variantstitle.gu="…" on the use adds .gu variants to every attribute that uses %{title}.
<if test="%{p}">…<else>…</else></if>kept when the value is not empty, 0, false, no or none; test="%{kind} == step" compares text; not="…" inverts.
<each items="%{items}" as="it" sep="|">once per item (empty items skipped): %{it}, %{it_i} (0-based), %{it_1}, %{it_n}, %{it_last}; an item title :: detail gives %{it.0}, %{it.1} (or names with fields="title,detail"). n="3" counts instead; sep="lines" splits on new lines or ‖, keep="1" keeps blank items.
%{dict[p]}(0.7) the entry of <dict id="dict"><e k="…" v="…"/>…</dict> (in the library, or the document) whose key is p's value; an unknown key is an error with "did you mean". %{p:sum} adds up p's numbers, %{p:count} counts its | items. In <each> also %{it_prev}, %{it_next} and %{it_acc} (sum of the items before). Defaults may hold commas inside quotes: colors='$a, $b'.
<slot/>the use's children; <slot name="x"/> takes the children marked slot="x".

A component may expand to scenes (used in <timeline>), to nodes (in a scene or group) or to other components. Errors name the use's line: unknown component or prop (with "did you mean"), missing prop, unknown param.

13.4 Flattening

TSVG.flatten(xml, libs) turns a document with imports into plain TSVG; TSVG.loadLibs(xml, {fetchText, base}) loads what it imports. Packages (tsvg pack, tsvg make) store the flattened document as main.tsvg, the original as source.tsvg and the library files under lib/, so every player plays them, offline. Players that load a .tsvg with imports flatten it themselves. tsvg lib lists the built-in libraries; tsvg lib report prints each component with its props.

Built-in: tsvg:base (shared look), tsvg:report (title, list, shot, stat, compare, code), tsvg:explainer (title, point, chapter, steps, stat, quote, picture, versus, outro), tsvg:charts (bars, hbars, line, pie, ring, counter, spark: one tag with a list of numbers), tsvg:fx (grain, vignette, scanlines, leak, flash overlays; grade, glow, shake, beat wrappers), tsvg:icons (2,104 Lucide icons, ISC: <i:icon name="rocket" size color drawin/>; tsvg icons rock finds names).
